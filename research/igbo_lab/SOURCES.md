## Published-source expansion

The user chose published sources rather than adding new AI-authored practice dialogues. `aya-originals` selects the same original Aya dataset with the fixed viewer filter `"language_code"='ibo' AND "annotation_type"='original-annotations'`. The filtered endpoint became available after the earlier mixed-language scans. The saved sample contains **500 unique candidate pairs**, after processing 542 filtered matches; the viewer reported 707 matches. The successful attempt used 344,116 response-body bytes over 15 counted requests, with no audio. The source card/contributor attribution and observed Hub head remain preserved. Filtering is rechecked locally; there is no unfiltered/full-dataset fallback.

`data/aya_originals_published_review_v1.jsonl` records 114 explicit AI decisions: **72 retained, 42 excluded, 386 pending**. Twenty-eight decisions match earlier source IDs/content hashes and retain links/hashes to their prior review files; these are reused decisions rather than 28 new independent reviews. Fragment-only tasks were reclassified as plain references, and the prior substantively rewritten affirmation was excluded. The retained source material comprises 29 Q&A pairs and 43 vocabulary/proverb references. All retained rows are transparently edited/formatted derivatives; publisher `original-annotations` is not proof of human authorship or accuracy. Dialect labels remain as supplied, with no invented regional attribution or universal-synonym claims.

The separate immutable assembly `.build/IgboLab/curation/assemblies/55d5ff6b7e546915/` contains those 72 records plus the three previously reviewed Africanvoice excerpts: **75 records, 1,000 whitespace-delimited words**, split 58 train / 10 validation / 7 test. Africanvoice restrictions still apply to its excerpts. The older mixed/synthetic-source public pilot and its measured results remain preserved separately; they are not parents of this new assembly. No new training, token preparation or frozen-benchmark evaluation was performed. This sample remains mostly riddles, vocabulary and cultural/language Q&A rather than ordinary assistant dialogue.

New fact checks used Harvard's [ELIAS Igbo orthography lesson](https://elias.unix.fas.harvard.edu/languages/igbo/beginning/1/igbos-and-their-language) for the existing Aya alphabet/vowel inventories and the [official Uyo local-government page](https://uyolga.akwaibomstate.gov.ng/about) for the existing capital fact. Those pages are verification references, not imported training sources. Per-record verification links and correction reasons are preserved.

Prospective source: [IgboSynCorp / Replication Data for Igbo Natural Language Processing Tasks I](https://doi.org/10.7910/DVN/RXBNCZ), also listed by the [Lacuna Fund](https://lacunafund.org/datasets/language/), describes a spoken Igbo corpus. Dataverse's indexed terms show CC0, but file-level provenance/contents have not yet been inspected. The inspected repository page/API presented an access challenge, so **no files or audio were imported** and no challenge was bypassed. It is a lead for future speech-derived text, not an accepted conversation corpus. Public university lesson conversations also require a clear reuse basis before bulk import; no course dialogue was copied into this corpus.

## Published requests for the voice assistant

[masakhane/InjongoIntent](https://huggingface.co/datasets/masakhane/InjongoIntent), observed Hub head `fe4be3882a1614161dfe231ec793197bb74f4b44`, provides a more relevant source of everyday **user requests**. The [source paper](https://aclanthology.org/2025.acl-long.464/) describes native-speaker elicitation using CLINC examples as intent prompts, rather than simple translation of each English utterance. The Igbo `ibo` configuration has official train/validation/test splits. It supplies intent and slot annotations, **not assistant responses or audio**. The first sample retains text, intent, example identity and original split/row provenance, and omits slot annotations. Later version-2 aliases retain source slots with explicit mechanical validity flags, as described below; semantic correctness remains unverified.

Attribution: Hao Yu and colleagues, *INJONGO: A Multicultural Intent Detection and Slot-filling Dataset for 16 African Languages*, ACL 2025, pp. 9429–9452, [doi:10.18653/v1/2025.acl-long.464](https://doi.org/10.18653/v1/2025.acl-long.464). Preserve the publisher card and cite its CLINC source. The Hub declares Apache 2.0, while the paper's dataset statement says CC BY 4.0. Both statements are retained in the import/curation evidence; do not silently replace one with the other or omit attribution when copying the records. The paper's human/native-speaker description is a provenance claim, separate from our **AI-only** review.

The first request sample contains 160 utterances in eight selected classes: `alarm`, `calendar_update`, `make_call`, `play_music`, `shopping_list_update`, `text`, `time`, `weather`. Acquisition used 79,020 HTTP-body bytes and 28 requests; no audio, weights or full dataset files. The first filtered-endpoint attempt returned HTTP 500 and installed nothing. The successful strategy explicitly reads small, fixed class-block ranges from the observed release, checking official split sizes, actual row indices and every returned intent. It aborts if that source layout changes. This is a stratified convenience sample, not a random sample or coverage of all 40 intents.

Codex read all 160 and retained 155: 123 unchanged and 32 edited. Edits are outer whitespace/NFC plus four explicitly identified CSV-style quote repairs, with supplied names and dialect spellings preserved. Five exclusions cover uncertain appointment wording, a near-duplicate alarm, a call-history question labelled `make_call`, a shopping reminder labelled as a list update, and an alarm/reminder request labelled `time`. Original labels are never silently changed. No new dialogue or assistant answer was authored. Retained official splits are 111 train / 16 validation / 28 test, with all eight classes represented in each; no source-text group crosses splits and no exact frozen reply-evaluation prompt overlaps.

The immutable request-only assembly is `.build/IgboLab/curation/assemblies/90cbf2af9a0dfd46/` (1,417 whitespace words). It is separate from the earlier 75-record reply/language assembly and the active token corpus. Its accompanying source/review evidence remains under `imports/injongo-igbo/` and `curation/injongo-igbo/`; copy the manifest, source card and attribution note with any exported records. It has no generated-reply targets, English/mixed-language coverage or independently verified audio. No training, app integration, actual calls/messages/calendar actions or frozen-benchmark rerun occurred.

## Intent prototype background and evaluation

The first request-classification experiment reuses the reviewed INJONGO sample above. Its background set extracts only the user-question portion of the 29 existing source Q&A pairs in the published-source Aya assembly `55d5ff6b7e546915`. `data/intent_background_review_v1.jsonl` records explicit AI judgements that these riddles, definitions, cultural questions and factual questions fall outside the eight selected task categories. No new question, translation or answer was authored. Input extraction and local `unknown` labels are task-specific AI derivatives, not independent native-speaker annotation or authentic spoken conversation.

Both source folds remain intact: INJONGO 111/16/28 plus Aya questions 20/5/4 yield 131 train / 21 validation / 32 test. Source IDs, content hashes, source groups and splits accompany each frozen query under `intent_experiments/intent-prototype-v1/dataset.jsonl`; the original published records and decisions remain preserved. This is a narrow out-of-scope assessment, since it does not include unseen INJONGO action classes or a representative English/mixed-language sample. The neural reply benchmark is separate and was not rerun. Read the experiment result and all errors before using its scores; no phone actions or speech-quality claims follow from intent labels.

## Version-2 detail references and controlled evaluation

`data/request_details_v2_review.jsonl` adds **AI span annotation**, not new dialogue, translation or assistant answers. All 96 records reference unchanged published validation/test utterances by source/content identity, normalized-text hash and exact UTF-8 byte positions. References cover unresolved contacts/relations, raw date/time expressions and geographic phrases; original source spelling is retained. There are 23 validation spans and 35 test spans. Unknown requests and unsupported detail types have explicit empty target sets. This gold is Codex AI review, not independently collected/native-speaker verification.

The raw publisher slot annotations were not used as gold or training labels: mechanical alignment did not establish correct semantic boundaries. Three explicit training-only examples in `request_source_slot_audit_v2.json` demonstrate that distinction. No raw sample, source annotation or prior review was overwritten to repair it.

The experiment excludes all 27 Orinode mixed-only unknown requests from fitting/calibration/testing, preserving them as a quarantined source file group. It uses only the new INJONGO and original-English CLINC requests for the candidate. The frozen v1 training snapshot/calibration supplies a baseline on the same fresh 59 cases; neither the v1 32-case test nor the reply benchmark was scored again. The new test was scored once after registration and validation-only calibration; its result is now inspected and must not become a tuning target. Preserve attribution and the original source terms with these AI-derived span labels as with the source utterances.
